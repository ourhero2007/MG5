## Devlog
1. In a large, open world game where there is a lot of potential terrain for characters to walk over, I think NavMesh would be more advantageous to use. For example there could be a game set in a huge forest with a lot of NPC characters the player can find and get quests from. Since we don't want NPCs to wander off and be impossible for the player to find, altering each NPCs NavMeshAgent components in the code will help restrict them to certain spaces on the overall NavMeshSurface component, which determines what ground is walkable by the Agents. In a smaller game with a more closed world where the gameplay involves collisions, using physics would be more advantageous. For example, in a fighting game that takes place in a small arena, using NavMesh would actually be worse because we actually want the movement to be dynamic, giving the player control over how they move through the space. So scripting using physics would be more advantageous in this situation.
2. Under the for loop, a variable called bird under the Bird class is assigned to a member variable called _birds with the [] accessing the "i" value in the parameters of the for loop. This makes sure that all the birds under the i value parameters set in the for loop are set to the _birds member variable as the loop continues. Then the if statement uses a method called Distance which measures the distance between two Vectors, the bird's transform position and the player's transform position. If this distance is less than or equal to the member variable _interactDistance, then the RunAway method will be called on the Bird gameobject. The parameter inside RunAway is likely what the bird is running away from, which is the _player's transform position. Based on the if statment, any bird thats i value falls under the scope of the for loop's parameters will run away from the player.
